# Contributing

Thanks for considering making contributions to `audera`. We are open to all contributions, check out the open [issues](https://github.com/Eleff-org/audera/issues) or open a new issue to spin up a conversation with us.

## Quickstart

1. Self-assign an open issue or create a new issue.
2. Fork the repository.
3. Implement changes, tests, and docs locally.
4. Push and open a PR.

## AI Usage

We accept contributions done in collaboration with coding agents. However, all contributions **must** follow the codebase conventions found in the coding agent instructions, see [AGENTS.md](/AGENTS.md). While we do accept code generated by coding agents, all contributions must be your own, you are responsible for the code you push and we are responsible for any code we merge and release.

### What does a successful contribution look like?

- The idea / concept / design solves a human problem or improves the human UX
- The change follows coding agent instructions
- You are able to articulate what the code does and why
- The change is verified end-to-end as a user on target hardware
- The change is simple, e.g. "the least buggy code is the code never written"
- Comments are minimal and the code is free from thinking context
- The change is comprehensive - incl. code, tests, and docs
- The change has already gone through multiple rounds of coding agent review (until no blocking changes remain)
- All commits contain co-authored statements transparently declaring the use of AI
